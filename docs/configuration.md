# 設定

OneStageROS の設定は、リポジトリ直下の `.env` ファイルに記述します。

```bash
cd ~/OneStageROS
cp .env.example .env
```

`.env` を編集したあとは、OneStageROS を再起動してください（`Ctrl+C` で停止し、もう一度 `npm start`）。

> `.env` には API キーなどの秘密情報が保存されます。`.env` は Git の管理対象外に設定されているため、`git push` してもリポジトリには含まれません。

以前のバージョンの設定ファイル（`server/.env`）も引き続き読み込みます。同じ項目が両方にある場合は、リポジトリ直下の `.env` が優先されます。

---

## 設定項目一覧

| 変数名 | 既定値 | 説明 |
|--------|--------|------|
| `ONESTAGE_EXPOSE` | `false` | ネットワーク公開の切り替え。[ネットワーク公開](#ネットワーク公開)を参照 |
| `ONESTAGE_AUTH` | （なし） | `token` にするとログインが必要になります。[ログイン](#ログイン)を参照 |
| `ONESTAGE_WORLD` | （なし） | 起動時に読み込むワールドファイル。[ワールド編集](world-editing.md#ワールドファイルを起動時に読み込む)を参照 |
| `ONESTAGE_SPAWN` | （なし） | ロボットの初期位置 `"x y yaw"`。[ワールド編集](world-editing.md#ロボットの初期位置)を参照 |
| `GAZEBO_MODEL_PATH` | （なし） | SDF の `model://` を探すディレクトリ（コロン区切り） |
| `AI_BASE_URL` | `https://api.groq.com/openai/v1` | AI 解析に使う API の URL |
| `AI_MODEL` | `llama-3.3-70b-versatile` | AI 解析に使うモデル名 |
| `AI_API_KEY` | （なし） | AI 解析に使う API キー |
| `AI_SYSTEM_PROMPT` | （組み込みの指示文） | AI 解析の指示文を差し替える場合に指定 |

AI 関連の項目は、画面上の「AI解析 設定」から保存することもできます（[デバッグログ](debug-log.md#ai-解析)を参照）。

### コマンドラインや Docker で指定する

`.env` を使わずに、起動時に環境変数として渡すこともできます。コマンドラインで指定した値は `.env` の値より優先されます。

```bash
ONESTAGE_WORLD=ros2_ws/src/my_pkg/worlds/room.world npm start
```

Docker の場合は、`docker-compose.yaml` の `environment:` に書くこともできます。コンテナを作り直しても設定が消えないため、Docker で常に必要な設定（`ONESTAGE_EXPOSE=true` など）はこちらに書くことをおすすめします。

## ネットワーク公開

ブラウザから OneStageROS に接続するポートは `3000` だけです。
バックエンド（`8000`）と ROS Bridge（`9090`・`9091`）は、どの設定でも OneStageROS を動かしている PC（またはコンテナ）の内部（`127.0.0.1`）でのみ待ち受け、ブラウザからの通信は `3000` を経由して中継されます。起動時のログに表示される `8000`・`9090`・`9091` は内部用のポートで、公開する必要はありません。

`ONESTAGE_EXPOSE` で、`3000` にどこから接続できるかを切り替えます。

| 値 | 接続できる範囲 | 主な用途 |
|----|----------------|----------|
| `false`（既定） | OneStageROS を動かしている PC（`localhost`）のみ | 自分の PC で ROS 2 と OneStageROS を動かす |
| `true` | ネットワーク上の他の PC、Docker のホスト機 | Docker コンテナ内で動かしてホスト機のブラウザから使う／別の PC のブラウザから使う |

### Docker で使う場合

コンテナ内で OneStageROS を動かし、ホスト機のブラウザから使う場合は、`ONESTAGE_EXPOSE=true` を設定し、ポート `3000` だけを転送します。

```yaml
services:
  your_service:
    ports:
      # 127.0.0.1: を外すと、同じネットワーク上の誰でも OneStageROS（ターミナルを含む）を操作できるようになります
      - "127.0.0.1:3000:3000"
    environment:
      - ONESTAGE_EXPOSE=true
```

ホスト機のブラウザで `http://localhost:3000` を開いてください。

- Docker はホスト機への接続をコンテナの IP アドレスに転送するため、`ONESTAGE_EXPOSE=false` のままではホスト機のブラウザから開けません。
- `--network host`（`network_mode: host`）でコンテナを起動する場合は、`ONESTAGE_EXPOSE=false` のままホスト機のブラウザから利用できます。

> **注意**: `127.0.0.1:` を付けずに `"3000:3000"` と書くと、ホスト機のすべてのネットワークに公開されます。
> Linux の Docker は ufw などのファイアウォールの設定を通らずにポートを公開するため、ファイアウォールだけに頼らないでください。
> また、`ONESTAGE_EXPOSE=true` のときは、同じ Docker ネットワーク上の他のコンテナからも接続できます。気になる場合は [ログイン](#ログイン) を有効にしてください。

### 別の PC から使う場合

デモなどで、同じネットワーク上の別の PC のブラウザから使う場合は、ネットワーク公開とログインを両方有効にしてください。

```bash
ONESTAGE_EXPOSE=true
ONESTAGE_AUTH=token
```

別の PC のブラウザで `http://<OneStageROS を動かしている PC の IP アドレス>:3000` を開き、ログイン画面に [トークン](#ログイン) を入力します。

- ログインした人は、ホームディレクトリ内のファイルの閲覧・編集や、ターミナルからのコマンド実行ができます。トークンは信頼できる相手にだけ伝えてください。
- 通信は暗号化されません（HTTP）。信頼できるネットワークで使ってください。
- IP アドレスで開いてください。`localhost` と IP アドレス以外のホスト名（`mypc.local` など）では開けません（[アクセス元の確認](#アクセス元の確認)）。
- 使い終わったら、`.env` の 2 行を消して再起動し、`npm run token -- --reset` でトークンを再発行してください。
- 必要に応じて、OS のファイアウォールでポート `3000` を許可してください。

相手が SSH で接続できる場合は、ネットワークに公開せずに使う方法もあります。見る側の PC で次を実行し、ブラウザで `http://localhost:3000` を開きます。通信は SSH で暗号化されます。

```bash
ssh -L 3000:localhost:3000 <ユーザー名>@<OneStageROS を動かしている PC>
```

## アクセス元の確認

OneStageROS は、次のリクエストを常に拒否します。ブラウザで開いた他の Web サイトから、ファイルの読み取りやコマンドの実行をされないようにするためです。

- 他の Web サイトのページからのリクエスト
- 同じ PC の別のポートで動いている Web ページからのリクエスト
- `localhost` と IP アドレス以外のホスト名でのアクセス（DNS rebinding 対策）

この確認は、ブラウザ以外のプログラム（curl など）からの接続は防げません。ネットワーク上の他の PC から接続できる状態にする場合は、[ログイン](#ログイン) を有効にしてください。

## ログイン

`ONESTAGE_AUTH=token` を設定すると、OneStageROS の画面を開くときに、トークンによるログインが必要になります。
ネットワークに公開する場合（別の PC から使う場合など）に設定してください。

```bash
ONESTAGE_AUTH=token
```

- 画面を開くとログイン画面が表示されます。OneStageROS を動かしている環境（Docker の場合はコンテナ内）のターミナルで次のコマンドを実行し、表示されたトークンを入力してください。

  ```bash
  cd ~/OneStageROS
  npm run token
  ```

- トークンは初回起動時に自動で作られ、`~/.config/onestage-ros/token` に保存されます。再起動しても変わりません。起動時のログには表示されません。
- `ONESTAGE_EXPOSE=false` の場合、`npm start` で自動的に開くブラウザはそのままログインされます。
- ログインはブラウザごとに 30 日間有効です。
- 1 分間に 10 回を超えてログインを試すと、しばらくログインできなくなります。

トークンが他の人に知られた場合は、再発行してから OneStageROS を再起動してください。ログイン中のブラウザはすべてログアウトされます。

```bash
npm run token -- --reset
```
